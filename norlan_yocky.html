Fundamentos de un Sistema Operativo

Un Sistema Operativo (SO) es el software principal que gestiona los recursos físicos de una computadora y provee servicios esenciales para la ejecución de aplicaciones.

⚙

1. El Kernel (Núcleo)

Es el corazón del sistema operativo. Actúa como puente directo entre las aplicaciones y el hardware (CPU, memoria y dispositivos de E/S) operando en modo privilegiado para garantizar estabilidad y seguridad.

Monolítico (Linux) Híbrido (Windows / XNU)
⚡

2. Gestión de Procesos

El planificador (Scheduler) decide qué proceso utiliza el procesador y durante cuánto tiempo, permitiendo la multitarea real mediante hilos (threads) y cambios de contexto ultrarrápidos.

Multitarea Concurrencia Hilos
▦

3. Administración de Memoria

Asigna bloques de memoria RAM a cada programa en ejecución y aísla sus espacios para evitar corrupción de datos. Cuando la RAM física se llena, utiliza memoria virtual (Paginación / Swap).

RAM Física Memoria Virtual Paginación
📁

4. Sistemas de Archivos

Estructura lógica que organiza cómo se almacenan, indexan y recuperan los datos en unidades de almacenamiento (SSD/HDD), controlando permisos de lectura, escritura y cifrado.

NTFS ext4 APFS

Problemas Comunes y Soluciones Técnicas

Haz clic sobre cada incidente crítico para desplegar el diagnóstico de causa raíz y los pasos de resolución.

Crítico Pantalla Azul (BSOD) o Kernel Panic repentino
▾

Causa principal: Ocurre cuando el núcleo del sistema detecta un error irrecuperable, generalmente provocado por controladores (drivers) corruptos, incompatibles o fallos físicos en módulos de RAM.

Protocolo de Solución

  • Windows: Inicia en Modo Seguro, revierte controladores recientes y ejecuta sfc /scannow junto con DISM /Online /Cleanup-Image /RestoreHealth.
  • Linux / macOS: Revisa los registros del último arranque con journalctl -b -1 -p err para identificar el módulo del kernel responsable.
  • Hardware: Ejecuta un diagnóstico de memoria (MemTest86) para descartar sectores dañados en la RAM.
Rendimiento Consumo excesivo de RAM y lentitud extrema (Thrashing)
▾

Causa principal: Fugas de memoria (memory leaks) en procesos en segundo plano que provocan que el sistema dependa excesivamente del archivo de paginación en disco (intercambio constante).

Protocolo de Solución

  • Identifica el proceso que retiene memoria mediante el Administrador de Tareas o usando htop / top en terminal Unix.
  • Deshabilita servicios y aplicaciones innecesarias en el arranque del sistema (systemctl disable [servicio] en Linux).
  • Verifica que el archivo de intercambio (Swap / Pagefile) esté alojado en un SSD y no en un disco mecánico lento.
Almacenamiento Uso de Disco al 100% y bloqueo de interfaz
▾

Causa principal: Operaciones intensivas de lectura/escritura simultáneas, indexación de búsqueda descontrolada, actualizaciones pendientes o degradación física de sectores del almacenamiento.

Protocolo de Solución

  • Comprueba el estado de salud S.M.A.R.T. de la unidad usando herramientas como smartctl -a /dev/sda.
  • En Windows, verifica los procesos de SysMain y el servicio de Windows Search, y ejecuta chkdsk /f /r en el próximo reinicio.
  • Asegúrate de mantener al menos un 15% de espacio libre en SSD para permitir el correcto funcionamiento del algoritmo TRIM.
Arranque Error "No Bootable Device" o fallo en GRUB / BCD
▾

Causa principal: Corrupción en el gestor de arranque (Bootloader), cambio accidental entre modos UEFI y Legacy BIOS en la placa base, o pérdida de la partición EFI.

Protocolo de Solución

  • Accede a la configuración UEFI/BIOS y confirma que el orden de arranque apunte al disco principal y que el modo coincida con la instalación original (UEFI).
  • Reparar Windows (BCD): Arranca desde un medio de instalación, abre consola y ejecuta bootrec /fixmbr y bootrec /rebuildbcd.
  • Reparar Linux (GRUB): Inicia desde un Live USB, monta la partición raíz con chroot y reinstala el cargador con grub-install y update-grub.
